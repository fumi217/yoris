# 議事録・メモ

## 決定事項

### 作業分担

全員がフロントエンドとバックエンドの両方を触る。機能ごとに縦に切り、画面から API・DB まで 1 人が通しで担当する。

| 担当 | 領域 | 主な機能 |
|---|---|---|
| ようこ | 基盤・認証・決済 | 環境構築（Docker Compose、CI、ログの出し分け）、ログイン・役割・招待、管理画面のアカウント管理、J：Stripe、本番デプロイ・https、E2E テスト |
| みさき | AI | 多言語・ふりがなの仕組み（最初に用意して全員が使う）、F：問い合わせ AI エージェント（相談員の対応待ち一覧を含む）、D：翻訳・整文・訳し戻し・承認、E：変化の検知、プロンプトインジェクションの確認 |
| ゆう | 職員の画面 | C：記録（食事・機嫌・眠り）、B：開示設定と変更履歴、A：職員の返事、連絡帳の見返し、G：面会予約 |
| さとこ | 家族の画面・通知 | 家族の連絡帳、A：家族の「知りたいこと」、通知（メール・まとめ・アプリ内のお知らせ・通知設定）、献立表、施設からのお知らせ、H：アルバム |

### 進め方

- **最初の 3 日間で、全機能のミニマム版を作る**。そこから作り込んでいく。
- ミニマム版の共通ルール
  - 画面の見た目は整えない。ふりがな・多言語は後回し（日本語だけ）
  - 管理画面の代わりに初期データを使う（入居者・職員・テーマ・定型文・面会枠など）
  - 正常に動く道だけ作る。ただし、権限のチェック（家族が他人のデータを見られない）は最初から入れる
  - 外部とのつなぎは最小限（メールは Mailpit に届けばよい、Stripe はテストモードで 1 回払えればよい、AI はツール 1〜2 個で答えられればよい）
- 3 日目の終わりに、全員で通しのデモをする（職員が記録 → 開示 → 家族が頼む → 職員が返事 → メールが届く → AI に質問 → Stripe で払う）

### まだ決まっていないこと

- 職員のログインの仕方（一人ずつログインするか、共有のタブレットで名前を選ぶか）。ログインと権限の作りが変わるので、Day 2 の「本当のログイン」までに決める（#11 の未決定事項）
