## 決めたこと
### デイリースクラムについて
- 前日の夕方～当日の朝9時頃までに、[MM-dd.md](MM-dd.md)を元にその日のファイル（例：10/24 の分は 10-24.md）を作り（なければ）、自分の欄の4項目を書く。「昨日」「今日」は、ファイルの日付から見た日。
  - 昨日やったこと：前の日にやったこと
  - 今日やること：ファイルの日付の日にやること
  - 進捗報告：前の日の終わりの時点の進み具合（issue・PR の番号があれば書く）
  - 困っていること・相談したいこと：あれば書く。急ぎのものは、書くのを待たずに Discord で伝える
- その日の PR は最初に書いた人が作り、ほかの人は同じブランチに push する。
  - 書く前に、そのブランチを pull して最新にする（`git fetch` → `git switch <ブランチ名>` → `git pull`）。
  - マージは、デイリースクラムのあと（10 時以降）に、手の空いている人が行う。マージの前に、全員の欄が書かれているかを確かめる。
  - マージしたあとに書き足したいことが出たら、新しいブランチと PR を作る。
- 朝9～10時の時間帯に、デイリースクラム（進捗共有）を行う。

### issue の進み具合の管理（GitHub Projects）
- issue は GitHub Projects の「[section9 開発](https://github.com/orgs/ms-engineer-bc26-08/projects/3)」で管理する（さとこが作成。issue 96 件が入っている）。
- 自動：issue が閉じたら Done、PR がマージされたら Done（プロジェクトの自動化で有効なことを確認済み）。
- 手動/自動：着手したら、自分のカードを In Progress に動かす（手動の場合は、ボードでドラッグするか、issue の右側の「Projects」から）。
- PR は、テンプレートの「Closes #」と「Refs #」の使い分けに従う。終わったタスクの tasks.md のチェックは、実装と同じ PR に含める。

- 頼まれた人は、見たら 🙆、レビューが終わったら ✅ の絵文字をそのメッセージに付ける。
