# デイリースクラムの基本的な進め方

## 時間と頻度: 1日1回、15分以内で実施する

- 朝9～10時の時間帯に実施する（[10-23.md](10-23.md) で決定）
- ファシリテーターは基本的にはリーダーが行ってください。リーダー不在の場合はメンバーが代理で行ってください。

## 参加者: メンバー全員

- 参加できない場合は記載しておくandあとから読んで状況をキャッチアップしておく

## 内容: 各メンバーが以下の4点を共有する

- 昨日やったこと
- 今日やること
- 進捗の報告
- 仕事を進めるうえでの問題点や困っていること

## 書き方（[10-23.md](10-23.md) で決定）

前日の夕方～当日の朝9時頃までに、[MM-dd.md](MM-dd.md) を元にその日のファイル（例：10/24 の分は `10-24.md`）を作り（なければ）、自分の欄の4項目を書く。

「昨日」「今日」は、ファイルの日付から見た日。月曜日のファイルの「昨日」は、前の金曜日。

| 項目 | 書くこと |
|---|---|
| 昨日やったこと | 前の日にやったこと（PR・issue の番号を添える） |
| 今日やること | ファイルの日付の日にやること |
| 進捗報告 | 前の日の終わりの時点の進み具合（issue・PR の番号があれば書く） |
| 困っていること・相談したいこと | あれば書く。急ぎのものは、書くのを待たずに Discord で伝える |

デイリースクラムは15分以内なので、細かく書きすぎない。話すときは要点だけでよい。

### 材料の集め方

- 自分の PR：`gh pr list --state all --author <GitHub のユーザー名> --search "updated:>=<前の日（YYYY-MM-DD）>"`
- レビューした PR：`gh pr list --state all --search "reviewed-by:<GitHub のユーザー名> updated:>=<前の日>"`
- 担当の issue：`gh issue list --assignee <GitHub のユーザー名>`
- PR・issue に出てこない作業（調べもの・相談・途中の作業など）は、本人に確かめてから書く。推測で書かない

## Git の手順

- ブランチ名は `docs/context-MM-dd-daily`（例：`docs/context-10-24-daily`）。その日の PR は、最初に書いた人が作る。
- ほかの人は同じブランチに push する。書く前に、そのブランチを pull して最新にする（`git fetch` → `git switch <ブランチ名>` → `git pull`）。
  - その日の PR があるかは `gh pr list --head docs/context-MM-dd-daily` で確かめる。
- `docs/context/` の記録だけの PR なので、Approve なしでマージしてよい（github-workflow スキル）。
- マージは、デイリースクラムのあと（10 時以降）に、手の空いている人が行う。マージの前に、全員の欄が書かれているかを確かめる。
- マージしたあとに書き足したいことが出たら、新しいブランチと PR を作る。

## Claude に頼むとき

夕方に、次のように頼めばよい。

> docs/context/daily-scram/README.md のとおりに、明日（MM/dd）のデイリースクラムの自分の欄を書いて。
