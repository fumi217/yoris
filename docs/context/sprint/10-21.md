# 話したこと：issueの立て方について

- githubに上げるのは、tasks.mdを元にして誰かが行う。
- issueの理解をした上で進める場合は、自分の環境で一覧化をした上で、突合するのも手。

- 進め方の言語化をすると良い。
- 「一覧化」の認識がずれている可能性がある。言語化をして認識を合わせておく。
- tasks.mdの内容もそうですが、フォーマットもわかりづらいのであれば、わかりやすいように、整理してもらえると嬉しいかも。
- チェックするタイミングを「どの状態でいつやるか？」だけ認識を合わせた方が良い。

---

手順

1. 各々の担当範囲やドキュメントを詰める（spec.md～tasks.md）。
2. tasks.mdまでをマージする。
3. みさきの作成した資料を元に、全員の認識を合わせる。共有する際は、画面共有などで、githubには上げない。（githubに挙げるかどうかは、それを見てから決める）
4. （任意）必要があれば、tasks.mdを修正する
5. イシューテンプレを皆で確認し、イシューテンプレをブラッシュアップ（ブラッシュアップ要否は確認時に検討）。
6. githubに挙げるissueは、tasks.mdとイシューテンプレを元に、`taskstoissues`スキルを活用して誰かが一括で担う。
