# 画面設計

> 各機能の詳しい動き（ボタン・文言・エラー）は `specs/<機能>/spec.md`・`tasks.md`・`contracts/api.md` が正。この文書は、画面の一覧・つながり・並べ方だけをまとめる。

## 0. この版の範囲（あえて軽くしている理由と、今後の書き足し方）

**v1（10/23）は、ミニマム版（Day 1〜4・10/22〜10/27）で作る職員の画面と、家族の画面（面会の予約・連絡帳・知りたいこと・お知らせ）だけを書いた。**
**v2（10/26）で、作り込み（Day 5）の入居者一覧（E の目印・D の承認待ち）と記録の画面（E の目印の欄・D の「様子のメモを書く」・H の「写真を載せる」）の並べ方を書き足し、ミニマム版で作ってみて変えたことを書き戻した（#106）。**
**v3（10/29）で、アプリの名前 YORIS のロゴ（文字つき。全画面の左上）・キャラクター（家族のホームの右下）・お問い合わせの画面の刷新の予定を書き足した（[デザインの決めごと](./デザインの決めごと.md) の 12・13 章。案）。**

軽くしている理由:

- ミニマム版のしめきりまで 3 日しかなく、ほかの人がゆうの記録のテーブル（001-T025）と共通の関数（001-T038 の `get_disclosed_records`）を待っている。画面設計に時間をかけるより、先にそちらを作るため
- 画面の細かい動き（ボタン・文言・エラー）は、すでに各 spec の受け入れシナリオと tasks.md に書いてある。この文書に同じことを書くと 2 か所になり、食い違いやすい（tasks.md が正）
- ミニマム版は「見た目・ふりがな・多言語は後回し」（作業分担MTG のルール）なので、見た目の決まりは、作り込みの前に決めても間に合う

今後の書き足し方:

- ~~作り込み（Day 5・10/28）の前に、ゆうが書き足す~~：入居者一覧の作り込みの表示（E の目印、D の承認待ちの件数）、記録の画面の部品（E の目印の欄・H の「写真を載せる」）の並べ方 → v2 で書いた（下の「4」「5」の【作り込み】）
- **余裕があれば足すもの**：入居者一覧の 50 音順の並べ替え（下の「4」で【今後】と書いたところ）
- **家族の画面・管理画面は、それぞれの担当が書き足してよい**（家族の連絡帳・知りたいこと・お知らせ・アルバム＝さとこ、問い合わせ AI・様子のメモ＝みさき、ログイン・決済・アカウント管理＝ようこ）。書き足すときは「3. 画面一覧」に行を足し、細かい動きは spec へのリンクで済ませる
- 実際に作ってみて変えた並べ方は、この文書を直す（直したら PR で知らせる）

## 1. 設計方針

- **端末**：家族はスマートフォンのブラウザ、職員は施設のタブレットのブラウザ（PRD 8 章。対応する版は Safari 16.4・Chrome/Edge 111・Firefox 128 以降）
- **UI**：React（Vite）＋ Tailwind CSS。UI ライブラリは使わない（技術選定）
- **文言**：固定の文言は辞書（`frontend/src/i18n/ja.json`）から引く。ふりがなは 001-T083 でみさきがまとめて付ける（spec 003 の画面は 003-T035 でゆうが付ける）。家族の画面（UI-F01〜）は、ふりがなを出さない（Constitution 3.2.0 の UI 方針の例外。#260）。絵文字とアイコンを併用する（Constitution の UI 方針）
- **職員の画面**：文字の入力なしで、ボタンだけで記録・返事ができる（記録は入居者を選んでから 3 タップ以内、返事はリクエストを開いてから 3 タップ以内。spec 001 SC-003・SC-007）。職員への通知・音・画面を遮る表示は出さない（Constitution 原則 II）
- **見せる範囲**：事務員は職員の画面（入居者一覧・記録の画面）を開けない。家族は職員の画面を開けない（spec 001 contracts の役割、#45）
- **名前・ロゴ・キャラクター（案。10/29）**：アプリの名前は **YORIS（ヨリス）**。**全画面の左上に、ロゴ（文字つき）**を置く（家族の画面は、左にロゴ・右に入居者の呼び名。職員・管理画面は、左にロゴ・その右に題）。**家族のホーム（UI-F02）の右下に、キャラクター**を、下のメニューの上に置く（右下に固定して置くのはホームだけ。職員・管理画面には出さない）（少し上下に動く。押すと嬉しい顔になってから、お問い合わせへ移る）。大きさ・動き・重ならない決まりは、[デザインの決めごと 12 章](./デザインの決めごと.md#12-yoris-の名前ロゴキャラクター1029ゆうさんの案)

## 2. 画面遷移

ミニマム版の職員の画面:

```text
ログイン（ようこ）
  └─ 入居者一覧 UI-S01
       ├─ 入居者を選ぶ → 記録の画面 UI-S02
       │                  ├─ 「返事待ち」→ 職員の返事の画面 UI-S03 → 保存 → 記録の画面に戻る
       │                  ├─ 「今日の連絡帳を見る」→ 連絡帳の見返し UI-S04
       │                  ├─ 「様子のメモを書く」→ 様子のメモを書く UI-S05（spec 007。介護職員・リーダー）
       │                  └─ 【作り込み】「写真を載せる」→ 写真を載せる UI-S10（spec 005。さとこ）
       ├─ 「家族からのメッセージ」→ 家族からのメッセージの一覧 UI-S08 → 詳細 UI-S09（spec 004。#88）
       ├─ 【作り込み】「今日の面会：◯組」→ 今日の面会予定 UI-S12 →「予約の一覧へ」→ 面会の予約の一覧 UI-S11（spec 003）
       ├─ 【作り込み】「確かめていない目印」→ まだ確かめていない目印のある入居者だけに絞る（同じ画面。spec 006）
       └─ 【作り込み】「承認待ち」→ 様子のメモの承認待ち UI-S07（spec 007。リーダー・施設長）

生活相談員・施設長：上の「管理画面」→ 管理画面のトップ UI-A00 →「開示設定」UI-A01 など。「家族からのメッセージ」も、管理画面のトップから開ける（UI-S08）
事務員：ログイン → 管理画面のトップ UI-A00 →「家族からのメッセージ（対応待ち ◯件）」→ 一覧 UI-S08 → 詳細 UI-S09（spec 004）
```

事務員は職員の画面（入居者一覧・記録の画面）を開けないので、家族からのメッセージ（お金・書類の担当など）と、その対応待ちの件数は、管理画面のトップから入る（spec 004 の `GET /api/staff/messages`・`/count` は職員全員が使える。PR #155 みさき。#88 で置き場所を決めた）。

**「家族からのメッセージ」の画面（UI-S08・UI-S09）は、同じ画面を 2 つの入り口から開く**：職員の画面の入居者一覧の上の件数（`/staff/messages`）と、管理画面のトップの入り口（`/admin/messages`）。一覧から詳細へ進むときは、開いた側の URL の下でつなぎ（`/staff/messages/:messageId`・`/admin/messages/:messageId`）、「戻る」も同じ側に戻る。どちらから開いても、見えるメッセージは同じ（苦情は生活相談員・施設長にだけ。API が決める）。

**「面会の予約の一覧」（UI-S11）も、同じ画面を 2 つの入り口から開く**：職員の画面の今日の面会予定から（`/staff/visits`）と、管理画面のトップの入り口から（`/admin/visits`）。予約の一覧を見ることと取り消すことは職員のすべての役割ができる（spec 003 の R-06）が、介護職員・リーダーは管理画面を開けないため。

**戻るリンク（#256）**：上の「管理画面」「職員の画面」の文字でもトップに戻れるが、題にしか見えず気づきにくいため、管理画面はトップ（`/admin`）以外のすべての画面のいちばん上に「◀ 管理画面のトップへ」を出す（枠の `AdminLayout.tsx` に置くので、画面を足す人は何もしなくてよい）。職員の画面は、各画面の下に戻るリンクを置く（記録の画面・メッセージの一覧・面会の予約の一覧・今日の面会予定は「入居者一覧へ」、連絡帳の見返し・返事・メモを書く画面は記録の画面へ、メッセージの詳細は一覧へ。メッセージの一覧を管理画面で開いたときは、上の「管理画面のトップへ」だけ）

家族の画面（ミニマム版）:

```text
家族の画面の下のメニュー
  ├─ 連絡帳（ホーム）UI-F02
  ├─ 知りたいこと UI-F03 → テーマを選んで「送る」→ 送ったリクエストの一覧（返事の前なら取り消し）
  ├─ お問い合わせ UI-F05 → 自由な文で AI に質問（spec 004）
  ├─ お知らせ UI-F04
  └─ ☰ その他 →「面会」→ 面会の予約 UI-F01 → 「予約が確定しました」
```

下のメニューは 4 つ（spec 001 の Clarifications の Session 2026-10-26。#85）。面会・アルバム・設定は「☰ その他」から開く。

ログインのあとに最初に開く画面（001-T019。`frontend/src/auth/me.ts` の `homePathFor`）:

| ログインした人 | 最初の画面 | 開ける画面のまとまり |
|---|---|---|
| 家族 | 連絡帳（`/family`） | 家族の画面だけ |
| 介護職員・リーダー | 入居者一覧（`/staff`） | 職員の画面 |
| 生活相談員・施設長 | 入居者一覧（`/staff`） | 職員の画面・管理画面（上にリンクを出す） |
| 事務員 | 管理画面（`/admin`） | 管理画面だけ |

- 開けない画面の URL を直接開いたときは、その人の最初の画面に戻す（家族が `/staff` を開くと `/family`）。画面で隠すのは見た目のためで、守りは API の 403
- 管理画面の中の画面ごとに開ける役割が違うときは（開示設定は生活相談員・施設長だけ など）、その API の 403 で守る

## 5. 記録の画面の部品の並べ方（UI-S02）

上から次の順に並べる（v2 で作り込みの部品の置き場所を決めた）。

1. 入居者の呼び名・居室、日付
2. 【作り込み】⚠️ 目印の欄（E の `ChangeFlagPanel`。目印があるときだけ）。記録を付ける前に、何がいつもと違うかが目に入るように、記録のボタンより上に置く。そばに「気になるときは、看護職員・生活相談員に相談してください。急変は電話で」（spec 006 FR-004）
3. 返事待ちのリクエストがあれば「💬 返事待ち：◯件」（押すと UI-S03）
4. 【作り込み】「📷 写真を載せる」（H。職員の 4 つの役割すべて。さとこの画面へ）と「✏️ 様子のメモを書く」（D。**介護職員・リーダーだけに出す**。みさきの UI-S05 へ。spec 007 の `POST /api/staff/residents/{id}/memos` が CW・L だけのため）を、横 1 列に並べる（spec 005 の T015「記録の画面の上に、様子のメモと同じ場所に」）。文字を小さめにして 1 行に収め、記録のボタンが下に押し出されすぎないようにする
   - 写真を載せる画面は `/staff/residents/:residentId/album`（さとこが決めた。10/27 のデイリースクラム。「3. 画面一覧」の行はさとこが足す）
5. 食事：食事区分（朝ごはん・昼ごはん・夜ごはん・おやつ）のタブ → 5 段階＋「食事なし（外泊・入院など）」のボタン。まだ記録していない最初の区分を開いておく（多くは入居者を選んでから 2 タップで保存できる。#190）
6. 😊 機嫌・様子：3 段階のボタン
7. 😴 眠り（昨夜の）：3 段階のボタン
8. 「今日の連絡帳を見る」（UI-S04）、「入居者一覧へ」

- 押したら、その場で保存する（保存ボタンは置かない）。押し直したら上書きする（spec 001 US1 の受け入れシナリオ 2・3）。今付いている値のボタンは色を変える
- 急変・事故は電話で連絡する（この画面は緊急の連絡には使わない）

## 6. エラー表示

- エラーは API の `{"error": {"code", "message_key"}}` を受け取り、`message_key` で辞書の文言を出す（spec 001 contracts のエラーの形）
- 出す場所は、押したボタンのそば（記録・返事）か、画面の上（読み込めないとき）。入力した内容は消さない
- 例：返事を同時に保存したとき（409 `already_replied`）は「ほかの職員が返事をしました」、面会の時刻が埋まったとき（409 `visit_overlap` など）は選び直してもらう案内を出す。細かい文言は各 spec のとおり

## 7. 家族の連絡帳の並べ方（UI-F02）

上から次の順に並べる。

1. 未読の返事のカード（「表示名（職種）からの返事」。職種は辞書で引く。#263）。日付に関わらず一番上。カードが画面に出たら、自動で既読にする（家族で共有。research.md R-15）
2. 食事 → 機嫌・様子 → 眠り（見せない設定の項目は出さない。まだ記録がない欄は「まだ記録されていません」。ただし、おやつは毎日付けるとは限らないので、記録があるときだけ出す）
3. 画面の下に「緊急のときは、施設から電話します」

- 日付は、見出しの下の「◀ 前の日」「次の日 ▶」「今日へ」と、日付の選択（カレンダー）で切り替えて、過去の日を見る（001-T094）。今日より先は選べない（記録がないため。「次の日」は今日のとき押せない）。URL は `/family?date=2026-10-26`（今日は日付なし）。変な日付は今日にする。未読の返事は、見ている日に関わらず一番上に出る
- 記録は、共通の関数 `get_disclosed_records` を通して読む（直接読まない。001-T055）
