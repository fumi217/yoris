## 1. 選定方針

優先する順に並べる。

1. **課題要件を満たせること**（下表）。
2. **チームが理解しながら作れること**。スプリントレビューの Try「スケジュールに追われるよりも理解を優先」
   と、講師コメント「フレームワークの違いや、作るアプリに合わせたものを調べてみて決める」に合わせる。
   経験に差があるため、担当をまたいで助け合える（読める・直せる）ことを重視する。
3. **開発期間の 10 日間（SEC10・11）で動くものを出せること**。設定や運用に時間がかかる技術は避ける。
4. **このアプリに合っていること**。家族はスマートフォン、職員は施設のタブレットで使う。
   画面は日本語・インドネシア語・英語を切り替える。AI は医療判断をせず、
   施設が家族に開示した記録だけを根拠に答える。

| 要件 | 区分 | 対応する技術（全案共通） |
| --- | --- | --- |

| XSS・SQL インジェクション対策 | MUST | 表示時の自動エスケープ（React）、ORM によるパラメータ化 |

## 4. リスクと対応

| リスク | 対象 | 対応 |
| --- | --- | --- |
| Next.js のサーバー機能に業務処理を書き、フロントとバックの分離があいまいになる | 案1・案3 | 業務処理・DB アクセスはバックエンドだけに置くことをコーディング規約に明記し、レビューで確認する |
| 言語が 2 つになり、担当外のコードを読めない | 案2・案3 | 型は OpenAPI から自動生成。ペアでレビューする |
| AI が非開示の記録や推測で答える、プロンプトインジェクションで他人の記録を引き出す | 全案 | 入居者 ID と開示範囲はサーバーがログイン情報から決め、AI のツールはその範囲の記録しか返さない。医療的な質問は定型文で相談員につなぐ |
| 開示設定を変えたのに、キャッシュに残った古い設定で非開示項目が表示される | 全案 | 家族の連絡帳はキャッシュせず、開示設定だけをキャッシュする。開示設定を保存したら、そのキャッシュを必ず消す（期限も付ける） |
| Stripe の Webhook がローカルで受け取れず、決済の確認が遅れる | 全案 | Stripe CLI で Webhook をローカルに転送して開発する。実課金はしない |
| 本番デプロイ・https・ドメイン設定を後回しにして最終週に詰まる | 全案 | スプリント 1 から、最小構成（Hello World）を本番にデプロイしておく |
| Render の無料枠はスリープや制限があり、発表時に遅い | 全案 | 発表前に有料プランへの切り替えか、事前アクセスで起こしておく |
| 新しい技術の理解が追いつかない | 全案 | 採用ライブラリは表にあるものに限定し、追加するときはチームに共有して理由をこの文書に追記する |
| 共有の OpenRouter キーの上限を、テストやバグ（無限ループ）で使い切る | 全案 | 自動テストでは LLM をモックにする。エージェントのループに上限回数を付け、Redis で家族ごとの問い合わせ回数を制限する |
| OpenRouter キーが漏れる | 全案 | `.env` は Git に入れず、キー名の一覧の `env.example` だけ置く（先頭にドットを付けないのは、Claude Code の設定で `.env.*` を丸ごと読めなくしているため）。Git にコミットする前に、hook と CI でキーらしき値がないか確かめる。チャンネルに直接貼らない。漏れたらすぐ学校に連絡する |
| 選んだモデルの一部の提供元がツール呼び出しに対応しておらず、ツールが無視される | 全案 | リクエストに `provider: {"require_parameters": true}` を付け、対応した提供元にだけ送る |

## 5. AI エージェントの実装方針

### 構成

- OpenRouter は OpenAI 互換の API を提供しているので、**OpenAI の Python SDK** の接続先を OpenRouter に向けて使う。
  - 接続先：`base_url="https://openrouter.ai/api/v1"`、`api_key` は OpenRouter のキー（環境変数から読む）
  - モデルは `提供元/モデル名` の形で指定する。モデル名は環境変数にして、コードを変えずに切り替えられるようにする
- エージェントのループは**フレームワークを使わず自前で書く**（数十行）。ツールが 4 つ程度と少なく、
  処理の流れがコードから読めるので、選定方針 2（理解しながら作る）とテストのしやすさに合う。

### ループの流れ

1. `tools`（ツール定義）と会話履歴を付けて、`chat.completions.create` を呼ぶ
2. 応答に `tool_calls` がなければ、その文章を家族への回答にして終わる
3. `tool_calls` があれば、応答メッセージをそのまま履歴に追加してから、各ツールをサーバー側で実行する
4. 結果を `{"role": "tool", "tool_call_id": ..., "content": <JSON 文字列>}` として履歴に追加し、1 に戻る
5. ループには上限回数（例：5 回）を付け、超えたら相談員に回す

### ツール

| ツール | 内容 | 段階 |
| --- | --- | --- |
| `get_daily_records(date)` | 指定日の、家族に開示された記録を取得する | **最初に作る** |
| `escalate_to_staff(要約, 理由, 回答の下書き)` | 相談員に回す | **最初に作る** |
| `get_visit_slots(date)` | 面会の空き枠を取得する | 後回し |
| `create_visit_reservation(slot_id, 人数)` | 面会を予約する | 後回し |

- 入居者 ID は AI に指定させない。サーバーがログイン中の家族から決めて、ツールの中で使う。
- 医療・服薬・体調の解釈・苦情・記録にないことは `escalate_to_staff` に回す。
- 最初は**読み取りと相談員への引き継ぎだけ**にする。AI が間違えてもデータは壊れないため。
  Redis の MUST 要件は、セッション・開示設定のキャッシュ・問い合わせ回数の制限で満たせるので、
  面会予約がなくても影響しない。
- 面会予約を作るときは、AI は予約内容を提案するだけにして、家族が確認ボタンを押してから確定する。

### 使えるモデル（学校配布のキー）

配布されたキーで使えるのは以下だけ。OpenRouter のモデル一覧 API で、チャット用の 5 モデルは
すべてツール呼び出し（`tools`・`tool_choice`）に対応していることを確認した（2026-10-19）。

| モデル | OpenRouter のモデル ID | 提供元 | 用途 |
| --- | --- | --- | --- |
| DeepSeek V4 Flash 0731 | `deepseek/deepseek-v4-flash-0731` | DeepSeek | チャット |
| GLM 4.7 Flash | `z-ai/glm-4.7-flash` | Z.ai | チャット |
| GPT-5 Nano | `openai/gpt-5-nano` | OpenAI | チャット |
| gpt-oss-120b | `openai/gpt-oss-120b` | OpenAI | チャット |
| Gemma 4 26B A4B | `google/gemma-4-26b-a4b-it` | Google | チャット |
| Whisper 1 | — | OpenAI | 音声の文字起こし |
| Text Embedding 3 Small | — | OpenAI | 埋め込み（検索） |
| GPT Image 1 Mini | — | OpenAI | 画像生成 |

- どのモデルも小型・高速なモデルで、日本語の文章の質やツールを正しく選べるかはモデルによって差がある。
  **問い合わせの例を 10 件ほど用意して全モデルで試し**、エージェント用と要約用を決める。
  例：「今日のお昼は食べましたか？」→ 記録を参照して答える／「薬は増えましたか？」→ 必ず相談員に回す
  この例はそのまま、エージェントのテストシナリオにも使える。
- Whisper 1 を使えば、職員の記録を音声入力にできる（余力があれば）。

### 調査で確認した注意点（OpenRouter のドキュメントより）

- `tools` は、ツールの結果を返す 2 回目以降のリクエストにも**毎回付ける**必要がある。
- ツールの結果を追加する前に、モデルの応答メッセージ（`tool_calls` を含む）を履歴に追加する。抜けると、モデルが自分の要求した内容を見失う。
- `finish_reason` を確認してから `tool_calls` を処理する。
- 1 回の応答で複数のツールが呼ばれることがある（`parallel_tool_calls` の既定は有効）。順番に処理したい場合は `false` にする。
- `tool_choice` は `"auto"`（既定）を使う。特定のツールを強制する指定は、モデルによっては受け付けないため使わない。
- ツール呼び出しに対応したモデルだけを使う。モデル一覧の `supported_parameters` に `tools` があるかで確認できる。
- ストリーミングにすると `tool_calls` が分割されて届くため、最初はストリーミングなしで実装する。

## 6. フロントエンドの選定理由（React（Vite）に決定）

| 観点 | React（Vite） | Next.js |
| --- | --- | --- |
| バックエンドとの分離 | ◎ フロント専用なので、業務処理を書く場所がない | △ サーバー機能（API Routes・Server Actions）があり、FastAPI と役割がかぶる。書かないルールが必要 |
| 覚えること | ◎ React と React Router だけ | △ App Router、サーバー／クライアントコンポーネントの違いなど、独自の概念が多い |
| 画面遷移 | ○ React Router を追加する | ◎ ファイルを置くだけで画面が増える |
| 多言語（日・インドネシア・英） | ○ react-i18next | ○ next-intl |
| SEO・初回表示の速さ | △ | ◎ ただし、ログイン後に使う業務アプリなので必要性は低い |
| デプロイ（Render） | ◎ ビルドした静的ファイルを置くだけ | ○ Node のサーバーとして動かす |
| PWA（Web Push 通知） | ○ プラグイン（vite-plugin-pwa）で対応 | ○ 設定を追加して対応 |

**React（Vite）に決定した**。バックエンドを FastAPI に決めたので、Next.js の強み（サーバー機能・SEO）を
使う場面がほぼなく、分離のルールを守るコストだけが残るため。

## 7. 言語・道具の版と、開発の道具（骨組みを作るときに決定）

版は、実績があって安定しているものを選ぶ（10 日間で、版の新しさが原因の想定外の作業を増やさないため）。
ライブラリの版は `requirements*.txt`・`package.json` で固定し、全員と CI で同じ版にする。

| 対象 | 版・道具 | 選定理由 |
| --- | --- | --- |
| Python | 3.13 | 出てから 2 年たち、使われてきた実績が長い（2026-09 の 3.13.16 で安全上の修正だけの時期に入った）。3.14 は修正が続く版だが、実績を優先した。3.12 は section8 から引き継いだ値で、選んだ理由がなかった。使う予定のライブラリ（FastAPI・SQLAlchemy・psycopg・Alembic・redis・structlog・bcrypt・openai・stripe・Pillow）が、組み立て済みの配布物で入り、既知の脆弱性がないことを確かめた |
| Node | 24 | Active LTS（2028-04 まで）。22 は修正が限られる Maintenance LTS に入り、26 は LTS になる直前のため |
| PostgreSQL | 18 | 出てから 1 年。19 はまだリリース候補 |
| Redis | 8.10 | 開発用の版。本番の構成は T092（本番デプロイ）で決める |
| lint・整形（バックエンド） | ruff | 1 つの道具で書き方のチェックと整形ができる |
| lint（フロントエンド） | ESLint | Vite の今のひな形は oxlint だが、情報が多く、tasks.md の T005 とも合うため ESLint にした |
| 整形（フロントエンド） | Prettier（＋ eslint-config-prettier） | 4 人が同じファイルを触るので、書き方をそろえて、PR の差分に空白や改行だけの変更が混ざらないようにする。eslint-config-prettier は、ESLint の見た目の決まりを切って、Prettier とぶつからないようにする |
| テストの HTTP クライアント | httpx2 | FastAPI の TestClient が使う。starlette が httpx から httpx2（同じ作者）への移行を勧めているため |
| PostgreSQL のドライバー | psycopg 3（`psycopg[binary]`） | SQLAlchemy 2 が対応している、今の版のドライバー。古い psycopg2 は新しい機能が足されない。`binary` は組み立て済みの配布物で、コンテナに C のコンパイラーや libpq を入れずに済む |
| DB のセッション | 同期（`Session`） | FastAPI は同期の関数を別のスレッドで動かすので、施設 1 つの利用者数なら足りる。非同期（`AsyncSession`）は、遅延読み込みでエラーになりやすく、4 人で書き方をそろえる手間が増える |
| 選択肢のある列 | text ＋ CHECK 制約（`app/db.py` の `check_in`） | PostgreSQL の ENUM は、選択肢を足すマイグレーションに手間がかかる（取り消しにくい）。CHECK 制約なら付け替えるだけで済む |
| 版を固定するライブラリ | コードで直接 import するものだけ | 一緒に入るもの（Starlette など）まで固定すると、上げるときの手間が増える。Pydantic は FastAPI と一緒に入るが、初めて import するタスク（API の入力の形を確かめるところ）で `requirements.txt` に書く |
