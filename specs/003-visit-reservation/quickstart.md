# Quickstart: spec 003（面会予約）の通しの確認

spec 003 ができているかを、手で通して確かめる手順。Day 3 の通しのデモと、E2E テスト（Playwright）の元にする。
起動のしかた（`docker compose up -d`、マイグレーション、初期データ、開発用のユーザー切り替え）は
[spec 001 の quickstart.md](../001-family-priority-report/quickstart.md) と同じ。
API の形は [contracts/api.md](./contracts/api.md)、テーブルは [data-model.md](./data-model.md) を見る。

## 用意するもの

- spec 001 の quickstart の「起動」まで終わっていること
- 初期データ（`python -m app.seed`）に、面会の設定（1 日 2 組）と開始時刻の候補 8 つ（10:00〜15:30）が入っていること
- 確かめる日は、**明日から 4 週間先までの平日**を使う（以下では「その日」と書く）。明日を使うときは、今が 17 時より前であること

### 同時に予約したとき（テストで確かめる）

画面からは同時に押しにくいので、pytest のテスト（[research.md R-09](./research.md#r-09-テスト)）で確かめる。

| # | すること | こうなれば OK | spec |
|---|---|---|---|
| 8 | 2 つの家族が、同じ日の 13:00 と 13:30 を同時に予約する | 1 件だけ確定し、もう一方は 409 `visit_overlap` | US1・SC-002 |
| 9 | 1 組入っている日に、2 つの家族が 13:00 と 15:00 を同時に予約する | 1 件だけ確定し、もう一方は 409 `visit_day_full` | US1・SC-002 |
| 10 | 家族 A のログインで、家族 B の予約の id を指定して取り消しの API を呼ぶ | 404（作り込みの取り消しの API ができてから） | FR-015・SC-004 |
