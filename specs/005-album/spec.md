# Feature Specification: 家族が入居者の写真を見られるアルバム（H）

**Feature Branch**: `docs/spec-005-album`

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "H：アルバム（spec 005）。職員が日中の合間にタブレットで入居者の写真を撮って載せ、その入居者の家族だけがアプリで見られるようにする。文字では伝わらない日々の様子や行事の雰囲気を、写真で伝えるため（Constitution 原則 I・II）。載せるのは職員で、撮影だけの短い手間にする。見られるのはその入居者の家族だけ。撮るのは日々の様子や行事。ほかの入居者が写りこまないように撮るか、同意のあった写真だけを載せる。施設が家族に見せるかどうかを選べる対象に、アルバムも入れる（原則 IV）。家族の画面では連絡帳の中ではなく別の画面にし、メニューは下に『連絡帳・知りたいこと・お知らせ』の 3 つ、そのほか（面会・アルバム・設定）は『☰ その他』にまとめる（spec 001 の決定）。新しい写真が載ったら家族に通知する。載せた写真は削除できる。ファイルは JPG・PNG のみ（PDF は入れない）、10MB まで、位置情報などの撮影情報（Exif）を取り除く。保存は spec 001 のお知らせの添付と共通の仕組みを使い、ログインした家族と職員だけが開ける。範囲：Day 1〜3 のミニマム版には入れず、作り込み（Day 4〜8）で作る。"

## Clarifications

### Session 2026-10-21

- Q: 誰が写真を撮って載せるか？ → A: 職員が、日中のお世話の合間に、タブレットで撮って載せる。撮影だけの短い手間にして、職員の負担を増やさない（Constitution 原則 II）
- Q: 誰が写真を見られるか？ → A: その入居者の家族だけ。ほかの入居者の家族には見えない（Constitution 原則 IV）
- Q: どんな写真を撮るか？ → A: 日々の様子や行事など
- Q: ほかの入居者が写ってしまうときはどうするか？ → A: 写りこまないように撮る。または、写る入居者本人（本人が難しいときは家族）の同意のあった写真だけを載せる。アプリでの確認のチェックは持たない（デモでは載せるだけ。施設の運用で守る）
- Q: 新しい写真の通知は、載せたらすぐ送るか、まとめて送るか？ → A: まとめて送る。家族が選んだ頻度（毎日 20 時／毎週日曜 20 時／通知しない）に従い、記録のお知らせと同じまとめに入れる。通知が多すぎると嫌がられるため（spec 001 Session 2026-10-20 と同じ考え方）
- Q: 載せた写真は、どの職員が削除できるか？ → A: 職員（介護職員・リーダー・生活相談員・施設長）が、どの写真でも削除できる（事務員は spec 001 の職員の画面に入らないため含めない。PR #45 でゆうさんが確認）。ほかの入居者が写っていたなどの取り下げを、気づいた人がその場ですぐできるようにするため。誰がいつ削除したかは残す。家族は削除できない
- Q: 入居者が退去・入院したとき、写真と家族の閲覧はどうするか？ → A: この spec では扱わない。アプリに退去・入院に応じた自動の処理は持たず、必要なら施設が職員の画面から写真を削除する（運用）
- Q: 写真に一言コメントを付けられるか？ → A: 付けられる。写真ごとに 100 文字まで、任意で、書いても書かなくても載せられる
- Q: アルバムも、施設が家族に見せる・見せないを選べる対象にするか？ → A: 対象にする（記録項目・テーマと同じ開示設定に並べる。Constitution 原則 IV）
- Q: 家族の画面のどこに置くか？ → A: 連絡帳の中ではなく、別の画面にする。メニューは、下に「連絡帳・知りたいこと・お知らせ」の 3 つを置き、そのほか（面会・アルバム・設定）は「☰ その他」にまとめる（spec 001 の Clarifications の決定に合わせる）
- Q: 新しい写真が載ったとき、家族に通知するか？ → A: 通知する
- Q: ミニマム版（Day 3）に入れるか？ → A: 入れない。作り込み（Day 4〜8）で作る
- Q: 載せた写真は削除できるか？ → A: 削除できる
- Q: ファイルの形式と大きさは？ → A: JPG・PNG のみ（PDF は入れない）、10MB まで。お知らせの添付（spec 001 FR-034）と同じ決まりにそろえる

## 背景と解決する困りごと

| ペルソナ | 困りごと | この機能で変わること |
|---|---|---|
| 佐藤美紀（家族） | 文字の記録だけでは、母が楽しそうにしているか、行事でどんな様子かが分からず、聞きたくても施設に遠慮して電話できない | アプリを開くだけで、母の日々の様子や行事の写真が見られ、電話しなくても安心できる |
| 田中健太・シティさん（介護職員） | 家族のために記録を増やす余裕がない。日本語の文章を書くのも負担 | 文章を書かずに、撮影して載せるだけで家族に様子が伝わる（一言は書きたいときだけ） |
| 山本由美（生活相談員） | 「様子を知りたい」という家族からの電話や問い合わせに、一件ずつ対応している | 写真で様子が伝わり、様子を尋ねる電話が減る。見せる・見せないは施設が選べる |

## User Scenarios & Testing *(mandatory)*

> 全体が作り込み（Day 4〜8）の範囲で、ミニマム版（Day 1〜3）には入れない。
> User Story 1 を先に作り、User Story 2 以降は書き足して進める。
> 各ストーリーは、架空の入居者・家族・職員のアカウントと架空の写真があれば、単独でデモできる。

### User Story 1 - 職員が写真を撮って載せ、家族が見る (Priority: P1)

職員（田中さん・シティさん）は、お世話の合間にタブレットで入居者を選び、写真を撮って（または撮ってある写真を選んで）載せる。
載せるときに、写真ごとに一言コメント（100 文字まで）を書くこともできるが、任意で、書かなくても載せられる。
その入居者の家族（佐藤さん）は、アプリの「☰ その他」から「アルバム」を開き、日付ごとに並んだ写真を見る。
写真をタップすると大きく見られる。ほかの入居者の家族には、この写真は見えない。

**Why this priority**: 日々の様子を写真で伝える、というこの機能の目的そのもの。載せる側と見る側がそろって、はじめて価値が伝わる。

**Independent Test**: 架空の職員アカウントで入居者を 1 人選び、架空の写真（JPG）を載せる。その入居者の家族アカウントで「☰ その他」→「アルバム」を開いて写真が見えること、
別の入居者の家族アカウントでは見えないことを確認する。

**Acceptance Scenarios**:

1. **Given** 職員が職員の画面で入居者を選んでいる, **When** 「写真を載せる」で写真を撮って載せる,
   **Then** 写真が保存され、「写真を載せました」と表示される。コメントを書かなくても載せられる
2. **Given** 職員が、1 回の操作で複数枚（10 枚まで）の写真を選んでいる, **When** 載せる,
   **Then** 選んだすべての写真が、同じ入居者のアルバムに載る
3. **Given** 入居者の写真が載っている, **When** その入居者の家族が「☰ その他」→「アルバム」を開く,
   **Then** 載せた日ごとに、新しい日が上になるよう写真が並んで表示される。タップすると大きく表示される
4. **Given** 入居者 A の写真が載っている, **When** 入居者 B の家族がアルバムを開く,
   **Then** 入居者 A の写真は表示されない。写真の URL を直接開いても表示されない
5. **Given** 家族アカウントでログインしていない, **When** 写真の URL を直接開く,
   **Then** 表示されず、ログイン画面に案内される
6. **Given** 入居者の写真がまだ 1 枚もない, **When** 家族がアルバムを開く,
   **Then** 「まだ写真はありません」と表示される（空欄にしない）
7. **Given** 職員が写真に一言コメント（例: 「運動会で、玉入れを楽しみました」）を書いている, **When** 載せる,
   **Then** 家族のアルバムの写真の下に、そのコメントが文字としてそのまま表示される。コメントが 100 文字を超えるときは載せられず、文字数を案内する

### User Story 2 - 職員が載せた写真を削除する (Priority: P2)

職員は、間違えて載せた写真や、あとから「載せないでほしい」と言われた写真を、アルバムから削除できる。
削除すると、家族の画面からすぐ消え、元のファイルも保存先から消える。

**Why this priority**: ほかの入居者が写っていた、同意が取れなかったなど、載せてしまった写真をすぐ取り下げられないと、個人情報の面で安心して使えない。

**Independent Test**: 写真を載せたあと、職員の画面でその写真を削除し、家族の画面から消えること、写真の URL を直接開いても表示されないことを確認する。

**Acceptance Scenarios**:

1. **Given** 入居者の写真が載っている, **When** 職員がその写真を削除する（確認のうえ）,
   **Then** 家族のアルバムから、次に開いたときに表示されなくなる（5 分以内）
2. **Given** 写真を削除した, **When** 削除した写真の URL を直接開く,
   **Then** 表示されない（ファイルも保存先から消えている）
3. **Given** 写真を削除した, **When** 施設が履歴を確認する,
   **Then** 誰がいつ削除したかが残っている（写真そのものは残らない）
4. **Given** 家族アカウントでログインしている, **When** 写真を削除する操作（URL の直接指定など）をする,
   **Then** 拒否される（家族は写真を削除できない）

### User Story 3 - 施設がアルバムを家族に見せるかどうかを選ぶ (Priority: P3)

施設（生活相談員・施設長）は、記録項目・「知りたいこと」のテーマと同じ開示設定の画面で、アルバムを家族に見せる・見せないを選べる。
見せない設定にすると、家族の画面（メニュー・通知の選択肢を含む）からアルバムが消える。

**Why this priority**: Constitution 原則 IV（何を開示するかは施設が選ぶ）を守るため。写真は要配慮個人情報にあたるので、施設が安心して使い始められる必要がある。

**Independent Test**: 開示設定でアルバムを「見せない」にすると、家族の「☰ その他」にアルバムが出ず、アルバムの URL を直接開いても見られないこと、
「見せる」に戻すと、載せてあった写真がそのまま見られることを確認する。

**Acceptance Scenarios**:

1. **Given** 開示設定でアルバムが「見せる」になっている, **When** 家族が「☰ その他」を開く,
   **Then** 「アルバム」が表示される
2. **Given** 生活相談員が開示設定でアルバムを「見せない」に変える, **When** 家族が次に画面を開く,
   **Then** 「☰ その他」にアルバムが出ず、アルバムの URL を直接開いても写真が表示されない。通知の選択肢にもアルバムが出ない
3. **Given** アルバムを「見せない」にしている, **When** 職員が写真を載せる,
   **Then** 載せることはできるが、家族には見えず、通知も送られない。職員の画面に「いま家族には見せていません」と表示される
4. **Given** 開示設定を変えた, **When** 施設が変更の履歴を確認する,
   **Then** 変更した人・日時・変更内容（見せる／見せない）が残っている
5. **Given** 介護職員の役割でログインしている, **When** 開示設定の画面を開こうとする,
   **Then** 開けず、アクセスが拒否される

### User Story 4 - 新しい写真が載ったことを家族に知らせる (Priority: P4)

新しい写真が載ると、家族に「アルバムに新しい写真が載りました」と知らせが届く。知らせは spec 001 の通知の仕組み
（アプリ内のお知らせとメール）を使い、載せるたびにすぐ送るのではなく、記録のお知らせと同じ「まとめ」（毎日 20 時／毎週日曜 20 時）に入れる。文面には写真の中身を含めない。

**Why this priority**: 通知がなくても、家族がアプリを開けば写真は見られる。通知は、見に来てもらうきっかけを作るもので、作り込みの最後に置く。

**Independent Test**: 職員が写真を載せ、家族のお知らせ一覧と、メール（開発用のメールサーバー）に「アルバムに新しい写真が載りました」が届き、
メールに写真も入居者名も入っていないことを確認する。

**Acceptance Scenarios**:

1. **Given** 家族がアルバムの通知を選んでいる, **When** 職員が写真を載せる,
   **Then** 載せてもすぐには知らせず、家族が選んだ頻度（spec 001 FR-023）のまとめ（毎日 20 時、または毎週日曜 20 時）で、アプリ内のお知らせとメールの両方に「アルバムに新しい写真が載りました」と知らせが届く。頻度を「通知しない」にしている家族には届かない
2. **Given** 同じ入居者に、1 日のうちに何枚もの写真が載った, **When** 20 時のまとめが送られる,
   **Then** 載せた枚数の分だけ通知が届くのではなく、そのまとめの中で 1 回の知らせになる。20 時より後に載った写真は、次のまとめで知らせる
3. **Given** 知らせのメールが届いた, **When** 家族がメールを見る,
   **Then** メールには知らせの種類とアプリへのリンクだけがあり、写真・写真のファイル名・入居者名は入っていない
4. **Given** アルバムを「見せない」設定にしている, **When** 職員が写真を載せる,
   **Then** 通知は送られない
5. **Given** 家族が通知設定で、アルバムの通知をオフにしている, **When** 職員が写真を載せる,
   **Then** 通知は送られないが、アルバムには写真が表示される

---

### Edge Cases

- 写真が 10MB を超える、または JPG・PNG 以外のファイル（PDF・動画・名前だけ JPG に変えたファイルなど）を載せようとした場合 → 載せられず、理由（大きすぎる・形式が違う）を案内する。ファイルの中身で形式を確かめる（名前の拡張子だけでは判断しない）。
- 写真に位置情報などの撮影情報（Exif）が入っている場合 → 取り除いてから保存する。取り除いた写真を、写真の向きが変わらないように表示する。
- ほかの入居者が写ってしまったが、同意のある写真を載せたい場合 → 写る入居者のうち、載せる入居者のアルバムにだけ載る。ほかの入居者の家族にも見せたいときは、その入居者を選んで載せ直す。
- 職員が、まだ招待されていない（家族アカウントがない）入居者の写真を載せた場合 → 写真は保存され、家族アカウントができたあとに、過去の写真も含めて見られる。
- 通信が途中で切れて、写真の送信に失敗した場合 → 「載せられませんでした。もう一度お試しください」と案内し、載せたことになったように見せない。
- 同じ写真を、続けて 2 回載せてしまった場合 → 2 枚として載る。間違いは削除（User Story 2）で直す。
- 家族が、アルバムの写真を自分の端末に保存した場合 → アプリは保存を止められない。写真を削除しても、すでに保存された写真は消せないことを、運用の注意として施設に伝える。
- 施設が、アルバムを「見せない」に変えた場合 → 保存済みの写真は残り、「見せる」に戻すとそのまま見られる（写真は削除されない）。
- 入居者が退去・入院した場合の写真の扱い → この spec では扱わない（施設の運用で、必要なら削除する）。

## Requirements *(mandatory)*

### Functional Requirements

**写真を載せる（職員）**

- **FR-001**: System MUST 職員（介護職員・リーダー・生活相談員・施設長）が、入居者を選んで、タブレットで写真を撮る、または端末にある写真を選んで、その入居者のアルバムに載せられる。
  1 回の操作で 10 枚まで選べる。写真に一言コメントを付けるかは任意で、書かなくても載せられる（FR-023。Constitution 原則 II）。
  載せた職員と日時は残す。
- **FR-002**: （削除: 写真を載せるときの確認のチェックは、デモでは載せるだけなので持たない。ほかの入居者が写りこまないようにする・同意のあった写真だけを載せる、は施設の運用で守る。Session 2026-10-21）
- **FR-003**: System MUST 受け付けるファイルを JPG・PNG に限り、1 枚 10MB までとする。ファイルの中身が本当にその形式かを確かめ、それ以外は受け付けず、理由を案内する。
- **FR-004**: System MUST 写真に含まれる位置情報などの撮影情報（Exif）を取り除いてから保存する。保存は、spec 001 のお知らせの添付と共通の仕組み（FR-034）を使う。

**写真を見る（家族）**

- **FR-005**: System MUST 家族が、家族の画面の「☰ その他」から「アルバム」を開き、自分の入居者の写真を載せた日ごとに、新しい日が上になるよう一覧で見られる。タップすると大きく表示される。
  さかのぼる日数に制限は設けず、過去の写真もすべて見られる（連絡帳と同じ）。
- **FR-006**: System MUST 家族アカウントには、自分の入居者の写真だけを見せ、ほかの入居者の写真を見られないようにする（写真の URL を直接開いても同じ。Constitution 原則 IV）。
- **FR-007**: System MUST 写真のファイルを、ログインした家族（自分の入居者の分）と職員だけが開けるようにする。URL を知っていても、ログインしていなければ開けない（spec 001 FR-034 と同じ）。
- **FR-008**: System MUST 写真がまだない場合は「まだ写真はありません」と表示し、空欄にしない（spec 001 FR-017 と同じ考え方）。
- **FR-009**: System MUST 載せた写真を、5 分以内に家族のアルバムに反映する（spec 001 FR-018 と同じ）。
- **FR-010**: System MUST 家族の画面のメニューを、下に「連絡帳・知りたいこと・お知らせ」の 3 つ、そのほか（面会・アルバム・設定）は「☰ その他」にまとめる形にする（spec 001 Clarifications の決定）。
  アルバムの置き場所は、連絡帳の中ではなく、この「☰ その他」の中の別の画面とする。

**写真を削除する**

- **FR-011**: System MUST 職員（介護職員・リーダー・生活相談員・施設長）が、載せた写真を削除できる。削除するときは確認を出す。家族は写真を削除できない。
- **FR-012**: System MUST 写真を削除したら、家族の画面から表示しなくなる（5 分以内）。元のファイルも保存先から消し、写真の URL を直接開いても表示されない。
  削除した職員・日時は残す（写真そのものは残さない）。

**開示設定（施設）**

- **FR-013**: System MUST 施設（生活相談員・施設長の役割）が、spec 001 の開示設定（FR-009）の画面で、アルバムを家族に「見せる」「見せない」を選べる。
  設定は施設全体で一括とし、全入居者の家族に同じように適用する。初期値は「見せる」とする。
- **FR-014**: System MUST アルバムを「見せない」設定にしたとき、家族のメニュー・アルバムの画面・写真の URL・通知の選択肢・通知のいずれにも、アルバムを出さない（spec 001 FR-010 と同じ）。
  写真は削除せず、「見せる」に戻したら、そのまま見られる。
- **FR-015**: System MUST 開示設定の変更を、変更者・日時・変更内容とともに記録する（spec 001 FR-011 と同じ）。変更は、次に家族が画面を開いたときに反映する（spec 001 FR-012 と同じ）。
- **FR-016**: System MUST アルバムを「見せない」設定のときも、職員が写真を載せることはできる。その場合は職員の画面に「いま家族には見せていません」と表示する。

**通知（spec 001 FR-023 の通知の仕組みを使う）**

- **FR-017**: System MUST 新しい写真が載ったとき、アルバムの通知を選んでいる家族へ、アプリ内のお知らせとメールで「アルバムに新しい写真が載りました」と知らせる。
  家族が通知設定で選べる内容に「アルバムの新しい写真」を加える（初期値は選んだ状態。アルバムを見せない設定のときは選択肢に出さない）。
- **FR-018**: System MUST アルバムの知らせを、spec 001 FR-023 の頻度の設定（1日1回まとめて（毎日 20 時）／1週間に1回まとめて（毎週日曜 20 時）／通知しない）に従って、記録のお知らせと同じまとめに入れる。
  載せるたびにすぐ知らせることはしない。まとめる間に何枚載せられても、知らせは 1 回にする。20 時より後に載せた写真は、次のまとめで知らせる。
  まとめる記録も写真も 1 件もないときは送らない。
- **FR-019**: System MUST 通知の文面（メール・アプリ内のお知らせとも）には、知らせの種類とアプリのアルバムへのリンクだけを載せ、写真・写真のファイル名・一言コメント・入居者名は載せない（spec 001 FR-023 と同じ考え方）。
- **FR-020**: System MUST 緊急の連絡にはアルバムを使わない。急変・事故などは、これまでどおり人が電話で連絡する（spec 001 FR-028・Constitution 原則 III）。

**画面の表記・安全性**

- **FR-021**: System MUST アルバムの固定の文言（見出し・ボタン・案内文）は、spec 001 FR-021 の表記のルール（やさしい日本語・すべての漢字にふりがな・多言語の切り替え）に従う。
- **FR-022**: System MUST 写真を、画像としてのみ表示し、ファイルの中身が画面の一部として実行されないようにする（spec 001 FR-025 と同じ）。
  一言コメント（FR-023）も、職員が自由に書いた文なので、翻訳・ふりがなの対象外とし、文字としてのみ表示する（入力に含まれるタグやスクリプトは実行されない）。
- **FR-023**: System MUST 職員が、写真ごとに一言コメント（100 文字まで）を付けられる。コメントは任意で、書かなくても保存できる。
  付けたコメントは、家族のアルバムの写真の下にそのまま表示する。コメントは、載せた後に直したり消したりはできない（直したいときは写真を削除して載せ直す）。

### Key Entities *(include if feature involves data)*

- **アルバムの写真**: 入居者 × 1 枚の写真。載せた職員・載せた日時、一言コメント（任意・100 文字まで）、削除した職員・日時（削除したとき）。写真のファイルそのものは、spec 001 のアップロードされたファイルの仕組み（種類に「アルバム」を加える）で保存する。
- **開示設定**（spec 001）: 項目に「アルバム」を加える（施設全体で一括、初期値は見せる）。変更の履歴を残す。
- **お知らせ**（spec 001）: 種類に「アルバムの新しい写真」を加える。
- **通知設定**（spec 001）: 家族が選べる内容に「アルバムの新しい写真」を加える。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 職員が入居者を選んでから 1 枚の写真を載せ終わるまで、30 秒以内・4 タップ以内（入居者を選ぶ → 写真を載せる → 撮る → 載せる）で、コメントを書かなければ文章の入力が 0 回である（デモ前にチーム内で計る。Constitution 原則 II）。
- **SC-002**: 家族が「☰ その他」→「アルバム」を開いて、最新の写真が見られるまで、2 タップ以内である（連絡帳の画面から）。
- **SC-003**: 家族アカウントで、ほかの入居者の写真を見る操作（画面・URL の直接指定）がすべて拒否され、ログインしていない人は写真のファイルを開けない（テストシナリオで確認）。
- **SC-004**: JPG・PNG 以外のファイルや 10MB を超えるファイルは載せられず、載せた写真の位置情報（Exif）がファイルに残っていない（テストシナリオで確認）。
- **SC-005**: 職員が写真を削除してから 5 分以内に、家族の画面から消え、写真の URL を直接開いても表示されない（テストシナリオで確認）。
- **SC-006**: 開示設定でアルバムを「見せない」にすると、家族のメニュー・URL・通知のどこにもアルバムが出ない（テストシナリオで確認）。
- **SC-007**: 通知のメールに、写真・ファイル名・入居者名が 1 件も含まれない（テストシナリオで確認）。
- **SC-008**: デモで、職員が写真を載せ、家族が電話をせずにその写真を見るところまでを、アプリだけで見せられる。

## Assumptions

- 全体が作り込み（Day 4〜8）の範囲で、ミニマム版（Day 1〜3）には入れない。作る順番は User Story 1 → 2 → 3 → 4 とする。
- 写真を載せられるのは介護職員・リーダー・生活相談員・施設長とし、削除も同じ役割ができる（現場でその場で取り下げられるようにするため）。事務員は、spec 001 の職員の画面（入居者の選択）に入らないため含めない。開示設定を変えられるのは、spec 001 FR-009 と同じ生活相談員・施設長。
- 写真には、任意で一言コメント（100 文字まで）を付けられる。書かなくても載せられることを優先する（Constitution 原則 II の「自由記述は任意の書き足しに限る」）。コメントは職員が自由に書く文なので、翻訳・ふりがなの対象外とする。
- 動画は扱わない。写真は、1 回の操作で 10 枚まで、入居者 1 人のアルバムに載せる。保存できる枚数の上限は、施設は 1 つ・入居者は最大 30 人のため設けない。
- 写真を家族が選んで一部だけ見せない・入居者ごとに見せる・見せないを変える、といった細かい設定は持たない（開示設定は施設全体で一括）。
- ほかの入居者が写っていないか、同意を得たかは、アプリでは確認せず、施設の運用で守る（デモでは載せるだけ）。画像から人を見分ける機能（顔認識など）は持たない。
- 同意の取り方（書面・口頭・誰からもらうか）は施設の運用で決める。アプリは同意書の管理をしない。本番で使うときに、確認のチェックを足すかは、そのとき決める。
- アルバムの通知は、spec 001 の通知の仕組み（FR-023）の頻度の設定に従ってまとめて送る（FR-018）。記録のまとめと 1 通にする（plan の [research.md R-06](./research.md#r-06-新しい写真の通知まとめに足す) で決定）。
- 時刻の判定は日本時間（Asia/Tokyo）で行う（開発前MTG の取り決め）。
- 保存先・写真の縮小（サムネイル）・表示の速さは plan で決める。
- spec 001 の `uploaded_files` の種類に `album` を加える変更（data-model.md の purpose）と、アルバム用の保存の処理は、plan で決める。
- 問い合わせ AI（F）が写真を参照することはしない（AI は写真を扱わない）。
- 作業分担：H は、家族の画面を持つさとこが担当する（README の体制）。写真を載せる職員の画面と保存の仕組みは、spec 001 のアップロードの共通の処理（さとこ）を使う。
- データは架空の入居者・家族・職員の写真のみを使う（Constitution 共通の設計制約。実在の人物の写真は使わない）。
